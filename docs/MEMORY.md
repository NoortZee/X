# Общая карта памяти

Единый источник адресов, сигнатур и смещений — **`memory/offsets.js`**.

Это относительные адреса и описание структур, а не абсолютные указатели конкретного запуска. База `libthieves.so` и реальные указатели объектов по-прежнему определяются внутри процесса игры (ASLR).

## Что находится в файле

| Раздел | Значения |
|---|---|
| `module_name`, `arch`, `game_version` | Библиотека и описание целевой сборки |
| `tas.signatures` | AOB-сигнатуры FRAME_FUNC, JUMP и функций разморозки |
| `tas.fallback` | Резервные RVA тех же функций относительно базы библиотеки |
| `tas.hero` | Смещения vtable, указателя физического тела и полей персонажа |
| `tas.body` | Смещения физических полей, тип и размер тела |
| `stones.parser_aob`, `parser_fallback` | Сигнатура и резервный RVA парсера соперника |
| `stones.rival_fields` | Смещения, имена и типы чтения полей соперника |
| `stones.rival_n_items`, `rival_items_ptr` | Количество элементов и указатель списка |
| `stones.item_fields`, `item_size`, `item_stride`, `item_first_ptr` | Поля камня и раскладка списка указателей |
| `platform` | Имя libc, структура времени и номер syscall x86_64 |

Константы протокола Phantom, FNV-хеша и IEEE-754 — не адреса памяти; они остаются рядом со своими алгоритмами.

## Как используются значения

`TAS/memory.rs` читает файл с диска и добавляет его перед исходником каждого Frida-агента:

```text
memory/offsets.js + TAS/agent.js
memory/offsets.js + stones/rival_hook.js
```

TAS подключает его через `TasAgent::load`, stones — через `load_hook_source`. Оба агента используют ссылки на разделы `MEMORY_LAYOUT`, например:

```js
const HERO = MEMORY_LAYOUT.tas.hero;
const BODY = MEMORY_LAYOUT.tas.body;
// ...
const body = hero.add(HERO.BODY_PTR).readPointer();
```

Вложенные объекты и массивы карты заморожены (`Object.freeze`), чтобы агент случайно не изменил значения. У каждого Frida-скрипта собственный контекст, но источник данных один и тот же.

Если файл отсутствует/пуст или JavaScript некорректен, загрузка завершается ошибкой. Встроенной копии старых адресов нет. Загрузчик проверяет архитектуру `Process.arch` перед выполнением кода агента. `game_version` — описание профиля, а не автоматическая проверка версии установленной игры.

## Обновление карты

1. Перепроверьте сигнатуры и раскладку структур для новой сборки игры.
2. Измените соответствующие значения в `memory/offsets.js` и описание `game_version`/`arch` при необходимости.
3. Проверьте синтаксис и mock-тесты:

   ```sh
   node --check memory/offsets.js
   node --test tests/memory_layout.test.js
   ```

4. Перезапустите TAS. Для отдельного stones-хука можно выполнить `stones stop`, затем снова загрузить модуль командой stones. Уже загруженные агенты не перечитывают файл автоматически.

После первоначальной пересборки с новым загрузчиком изменения **только `memory/offsets.js` не требуют пересборки Rust**. Не перемещайте файл отдельно от проекта: путь разрешается от корня рядом с `TAS/` и `stones/`, а не от текущего каталога терминала.

Исходные значения сохранены из прежних агентов для King of Thieves 2.84.1 x86_64. Совместимость с другой сборкой не гарантируется. История изменений хранится в `docs/CHANGELOG.md`.
