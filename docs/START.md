# Установка и запуск через start/

В `start/` ровно два исполняемых файла:

- `install.sh` — зависимости, серверы и сборка TAS;
- `start.sh` — развёртывание серверов в Waydroid, проверки, запуск TAS и очистка.

## Требования

Linux x86_64 с CachyOS/Arch Linux, Ubuntu/Debian или NixOS, `sudo`, уже установленный и инициализированный Waydroid с Android x86_64 и игрой. Установка самого Waydroid, Android-образа и APK зависит от дистрибутива и не выполняется этими скриптами.

Запускайте скрипты от обычного пользователя, **не через sudo**. Привилегии запрашиваются для отдельных операций. Для установки нужен интернет (pacman, APT или nix, GitHub, Google Android SDK, Rust, crates.io и PyPI) и несколько гигабайт свободного места.

## Установка

Из корня проекта:

```bash
./start/install.sh
```

На CachyOS/Arch используется `pacman -S --needed --noconfirm`: только зависимости TAS, **без полного обновления системы и без синхронизации баз** (`-y`). Уже актуальные пакеты пропускаются; выбранные зависимости и необходимые им пакеты могут быть обновлены. Обновление ОС и обслуживание зеркал остаются под контролем пользователя. Если зеркало недоступно или сохранённая база ссылается на удалённые пакеты, установщик остановится с ошибкой — он не переключается на `-Syu` и не меняет зеркала автоматически. Закройте другие менеджеры пакетов перед установкой.

На NixOS используется `nix profile install nixpkgs#…` **в профиль пользователя**: системная конфигурация и `/etc/nixos/configuration.nix` не меняются, `sudo` для пакетов не требуется. `--extra-experimental-features 'nix-command flakes'` передаётся явно, поэтому включать flakes в `nix.conf` не нужно. Так как `nix profile install` отказывается ставить уже установленный пакет, каждый инструмент сначала проверяется через `command -v`. NixOS определяется по `/etc/NIXOS` или `nixos-rebuild` и имеет приоритет перед `pacman`/`apt-get`: на NixOS они могут быть установлены через nix, но писать в store не умеют.

Команды `./start/install.sh` и `./start/start.sh` можно вызывать и из fish: скрипты запускаются своим Bash-интерпретатором. Если вы уже находитесь в каталоге `start/`, используйте `./install.sh` и `./start.sh` соответственно.

Установщик:

0. **Сначала** проверяет `config.yaml` и только потом что-либо устанавливает: нет файла — создаёт из `config.example.yaml` с правами `600`; файл есть и цел — пишет `config.yaml: exists and is intact — skipping`; файл битый (пустой, обрезанный, без секций примера, невалидный YAML) — переименовывает в `config.yaml.broken.<дата>` и создаёт заново.
1. Автоматически выбирает `nix` для NixOS, `pacman` для CachyOS/Arch или `apt-get` для Ubuntu/Debian и устанавливает ADB, компиляторы, libclang, OpenSSL, JDK 17, Python/venv/PyYAML и утилиты. В Arch `venv` входит в пакет `python`. Для SDK и сборки используется установленный JDK 17 без изменения системной Java по умолчанию. На NixOS `JAVA_HOME` выводится из `readlink -f "$(command -v javac)"`: пути `/usr/lib/jvm` там не существует.
2. При отсутствии Cargo устанавливает Rust stable через официальный rustup. На NixOS rustup не используется — его тулчейн не линкуется без FHS-путей; Cargo и Rustc ставятся из nixpkgs, и их отсутствие после этого считается ошибкой. **Нужен Rust 1.85 или новее**: `third_party/frida-rust` объявляет `edition = "2024"`, а nixpkgs на старом стабильном канале может отставать. Если сборка падает с `edition2024 is unstable`, обновите канал (`nixos-rebuild switch --upgrade`) или поставьте тулчейн через `nix profile install nixpkgs#rustup`.
3. Устанавливает отдельный Android SDK в каталог данных TAS. Проверяет архив инструментов по контрольной сумме из HTTPS-манифеста Google. Лицензии Android предлагается прочитать и принять интерактивно.
4. Получает `NoortZee/phantom_keymaper` на закреплённом коммите `bc4f338488f03f229e9a9812e4b48baee56a45d8` и собирает **Android-компонент `phantom-server.jar`**, необходимый TAS. Десктопный mapper/GUI для работы TAS не нужен и не устанавливается.
5. Скачивает модифицированный сервер из релиза `x86` репозитория `NoortZee/phantom-frida`, проверяет закреплённый SHA-256 архива, выбирает ELF x86_64 и устанавливает его под именем `sysmon`. Обычный upstream frida-server вместо него не используется.
6. Создаёт отдельный Python venv с версией клиента Frida из `third_party/frida-rust/frida-sys/FRIDA_VERSION`.
7. Выполняет `cargo build --release`, только если бинарник отсутствует или старше исходников (`TAS`, `catacombs`, `stones`, `memory`, `third_party`, `Cargo.toml`, `Cargo.lock`). На NixOS сборка идёт внутри `mkShell` (`nix develop`): pkg-config-файлы и заголовки лежат в `dev`-выходах, которых профиль пользователя не даёт, а `rustPlatform.bindgenHook` выставляет `LIBCLANG_PATH`. Голый `nix-shell -p` для этого не годится — он только правит `PATH` и не запускает setup-хуки.

Каждый шаг 2–7 перед установкой проверяет свой путь назначения и целостность файла: sha256-сайдкар рядом с артефактом, `classes.dex` внутри `phantom-server.jar`, ELF64 x86_64 для `sysmon`, импорт закреплённой версии `frida` в venv. Целое — пропускается с явным сообщением, повреждённое — переустанавливается с `WARN`.

Артефакты, SDK и исходники внешних проектов находятся в `${XDG_DATA_HOME:-$HOME/.local/share}/kot-tas`, а не в Git. Повторная установка не перезаписывает локальные изменения в клоне Phantom. Для обновления закреплённых версий нужно явно обновить коммит/URL/контрольную сумму установщика.

### Ошибка проверки Phantom origin

Установщик проверяет сохранённый в локальном клоне адрес `remote.origin.url`. HTTPS и SSH для `NoortZee/phantom_keymaper` равнозначны; пользовательские правила Git `insteadOf` сохраняются и не вызывают ложного отказа. Самостоятельно менять origin или удалять существующий клон скрипт не будет.

Если ошибка остаётся, проверьте локально:

```bash
git -C "${XDG_DATA_HOME:-$HOME/.local/share}/kot-tas/src/phantom_keymaper" config --local --get-all remote.origin.url
```

Ожидается один адрес репозитория `NoortZee/phantom_keymaper` на GitHub. Не публикуйте URL, если в нём есть токен или пароль. При другом origin сначала убедитесь, что это нужный клон, и исправьте адрес вручную; локальные изменения не удаляйте.

Предупреждение SDK Manager о переходе на Android CLI не является причиной ошибки origin: в данном сценарии установщик продолжает работу, если команды SDK завершились успешно.

### Ошибка `d8: /bin/bash: bad interpreter: Нет такого файла или каталога`

Так выглядит падение на NixOS:

```
.../build-tools/35.0.0/d8: /bin/bash: bad interpreter: Нет такого файла или каталога
Installation failed at line 281. TAS was not started.
```

`d8` в `build-tools` — это не бинарник, а shell-обёртка с шебангом `#!/bin/bash`; на NixOS такого пути нет, и ядро отказывается запускать файл ещё до Java. Установщик это распознаёт: если `d8` не запускается, а интерпретатор из его шебанга — `bash`, которого нет в системе, рядом создаётся исполняемая обёртка `${XDG_DATA_HOME:-$HOME/.local/share}/kot-tas/bin/d8`, которая вызывает тот же самый скрипт через `bash` установщика. Сам SDK не изменяется, а в логе появляется строка `d8: /bin/bash is missing; using the ... shim for ...`. Если причина другая (не Java, не права, битый SDK), установщик падает с явной ошибкой, а не подменяет файл.

На Arch/Ubuntu правка ничего не меняет: рабочий `d8` используется как есть.

### Ошибка `Unable to find libclang` / `frida-core.h: No such file` при сборке

Так выглядит падение `bindgen` на NixOS:

```
frida-build: core devkit not found, downloading from https://github.com/frida/frida/releases/...
thread 'main' panicked at bindgen-0.72.1/lib.rs:616:27:
Unable to find libclang: "couldn't find any valid shared libraries matching: ['libclang.so', ...],
set the `LIBCLANG_PATH` environment variable ..."
```

Причина: `nix-shell -p libclang` (и `nix shell`) только добавляет бинарники в `PATH` — setup-хуки не запускаются. Пакет `libclang` своего хука не имеет: `LIBCLANG_PATH` экспортирует `rustPlatform.bindgenHook`. Установщик собирает проект в настоящем `mkShell` (`nix develop --impure --expr …`), где подключены `rustPlatform.bindgenHook`, `pkg-config`, `gcc`, `clang`, `openssl`, `glib` и `gnumake`. Дополнительно `frida-core.h` начинается с `#include <glib.h>`, поэтому в `BINDGEN_EXTRA_CLANG_ARGS` добавляются cflags `glib-2.0 gobject-2.0 gio-2.0` — уже после хуков, чтобы их не перезаписало.

Если сборка падает с другой ошибкой clang, проверьте вручную:

```bash
nix --extra-experimental-features 'nix-command flakes' develop --impure --expr \
  'let pkgs = (builtins.getFlake "nixpkgs").legacyPackages.${builtins.currentSystem};
   in pkgs.mkShell { nativeBuildInputs = [ pkgs.pkg-config pkgs.rustPlatform.bindgenHook ];
                     buildInputs = [ pkgs.cargo pkgs.rustc pkgs.gcc pkgs.clang pkgs.openssl pkgs.glib ]; }' \
  --command bash -c 'echo "$LIBCLANG_PATH"; pkg-config --cflags glib-2.0'
```

Проверьте координаты и настройки Telegram в `config.yaml`: пример содержит фиктивный токен. Для отключения уведомлений установите `telegram.enabled: false`.

## Запуск

Запустите Waydroid и откройте King of Thieves, затем:

```bash
./start/start.sh
# Другой конфиг:
./start/start.sh /absolute/path/to/config.yaml
# Другой ADB-адрес:
TAS_ADB_DEVICE=192.168.240.113:5555 ./start/start.sh
```

Серверы запускаются **без дополнительных консолей**. В исходном терминале остаётся только интерактивный TAS. Konsole, X11/Wayland-переменные окружения и другой эмулятор терминала лаунчеру не нужны (сама игра по-прежнему должна работать в Waydroid).

В начале `sudo -v` запрашивает пароль в текущем терминале. Фоновые управляющие процессы используют `sudo -n`: повторных скрытых запросов пароля нет. Каждый процесс удерживает foreground-подключение `waydroid shell` с `exec` сервера внутри Android. Это не удалённый `nohup ... &`: локальные подключения продолжают жить, пока работают серверы. Для них создаются отдельные группы процессов в той же терминальной сессии, чтобы сохранить доступ к кешу sudo текущего терминала. Их stdin отключён от терминала, stdout/stderr направлены в `sysmon.log` / `phantom.log`.

ADB-адрес по умолчанию: `192.168.240.112:5555`.

Лаунчер выполняет `adb kill-server`, `adb start-server`, подключается к указанному устройству и проверяет доступность root в контейнере (`sudo -n waydroid shell`, без `su` внутри Android — в стоковом образе Waydroid его нет), ABI, запущенную игру и версию `sysmon`. Затем перезапускает старые sysmon/Phantom, копирует серверы в `/data/local/tmp`, запускает их через фоновые управляющие процессы и создаёт пробросы:

```text
tcp:41337 → localabstract:/data/local/tmp/sysmon.sock
tcp:27183 → tcp:27183
```

Локальные порты читаются из `frida.device` и `phantom.port` выбранного YAML; localhost обязателен. Конфиг разбирается как данные (`yaml.safe_load`), никогда не через `source`/`eval`. Интерпретатор выбирается так: системный `python3`, если в нём есть PyYAML (Arch, Debian), иначе `$DATA/venv/bin/python` — на NixOS у системного `python3` нет своих site-packages, а установщик кладёт PyYAML в venv на любом дистрибутиве. Если PyYAML нет ни там, ни там, запуск прерывается до обращения к ADB. Внутренний Android-порт Phantom — 27183. Пробросы создаются с `--no-rebind`. Проверяется настоящий PING/PONG Phantom и перечисление процессов через Frida, а не только открытие TCP-сокета.

TAS запускается с переданным конфигом и рабочим каталогом проекта. Отдельный наблюдатель каждые несколько секунд проверяет Frida RPC, доступность игры, PID серверов и управляющих процессов, а также продлевает sudo-сессию исходного терминала. Phantom PING выполняется до старта TAS, но не во время игры: отключение дополнительного клиента Phantom вызывает `cancelAll` и может помешать вводу. Если проверка не проходит, работа завершается с очисткой.

### Размер окна Waydroid и координаты тапов

Координаты тапов больше не привязаны к конкретному разрешению. После проверок устройства лаунчер читает реальный размер окна:

```bash
adb -s "$TAS_ADB_DEVICE" shell wm size
```

Если в выводе есть и `Physical size`, и `Override size`, берётся `Override size` — именно в это окно рендерит игра после изменения размера. Результат печатается (`Waydroid display: 1920x1048; ...`) и передаётся TAS через переменные окружения `KOT_TAS_SCREEN_WIDTH` / `KOT_TAS_SCREEN_HEIGHT`.

Если размер прочитать не удалось, запуск прерывается до развёртывания серверов с сообщением `Cannot read Waydroid display size`. Так тап не может уйти в точку, рассчитанную от чужого разрешения.

В `config.yaml` координаты задаются долями окна (`tap.position: "fraction"` + `x_frac`/`y_frac`, то же для `stones.skip_on_no_match`), поэтому на любом окне они попадают в то же место экрана. Режимы `center_lower_third` и `explicit` сохранены: `explicit` — абсолютные пиксели без масштабирования.

Секция `screen:` в конфиге переопределяет автоопределение. Она нужна только при запуске `target/release/kot-tas` напрямую, без `start.sh`: без лаунчера переменные окружения не установлены, и масштабированные режимы завершатся с понятной ошибкой вместо неверного тапа.

## Завершение и ограничения

**Ctrl+C во время команды TAS** отменяет текущую запись, повтор или LIVE и возвращает главное меню. Серверы и ADB-пробросы при этом остаются запущенными. Лаунчер пересылает SIGINT в отдельную группу TAS и продолжает ждать завершения приложения; наблюдатель игнорирует терминальный SIGINT.

Для полного выхода используйте `exit` / `q` в меню. Ctrl+C в самом меню завершает TAS согласно его текущему обработчику. До запуска TAS Ctrl+C отменяет развёртывание с очисткой.

При полном выходе, ошибке TAS, ошибке развёртывания, SIGTERM или закрытии терминала (SIGHUP) обработчик завершения:

- останавливает TAS и наблюдатель;
- завершает оба фоновых подключения Waydroid и их группы процессов;
- останавливает Android-процессы по PID-файлам этой сессии с проверкой имени процесса;
- удаляет удалённый временный каталог и только созданные этой сессией пробросы;
- выключает ADB-сервер;
- сохраняет локальную диагностику в `${XDG_DATA_HOME:-$HOME/.local/share}/kot-tas/sessions/session.*` (путь печатается при запуске и выходе).

`health.log` и `watch.log` заранее открываются обычным пользователем, до привилегированных операций и старта TAS. Если открыть их нельзя, запуск прервётся до развёртывания серверов. Во время мониторинга используются уже открытые дескрипторы: изменение прав записи к пути не должно прерывать исправную сессию. Лаунчер не выполняет рекурсивный `chown` и не ослабляет права доступа. Причины сбоя sudo, Frida/игры и проверки Android PID выводятся раздельно.

В каталоге диагностики находятся `sysmon.log`, `phantom.log`, `health.log` и созданные для сессии скрипты. Даже если сервер сразу завершится, его вывод не теряется после очистки. Старые каталоги диагностики можно удалить вручную после разбора ошибки.

Код выхода TAS сохраняется. При невозможности очистить Android-процессы выводится предупреждение с путём каталога сессии. Для Android-очистки используется Waydroid, поэтому она возможна и при потере ADB. Установка и запуск сериализованы через `flock`.

**Важно:** перезапуск/выключение ADB влияет на другие ADB-сессии пользователя. Старые sysmon и Phantom в Waydroid принудительно останавливаются. Не запускайте параллельно независимую сессию, использующую эти же серверы. Phantom слушает `0.0.0.0` внутри Android, как в ручном сценарии; используйте доверенную сеть.

Обработчик не может выполниться после SIGKILL, отключения питания или аварии ОС. Если сам контейнер исчез, завершить процессы внутри него невозможно; для обычных ошибок, сигналов и выхода очистка выполняется автоматически.

## Проверки без Android

ShellCheck — необязательный инструмент разработки, он не устанавливается как зависимость TAS. Для выполнения соответствующей команды установите его отдельно.

```bash
bash -n start/install.sh start/start.sh
shellcheck start/install.sh start/start.sh
python3 -m unittest discover -s tests -v
```

Тесты используют имитации ADB, sudo, Waydroid, Frida и TAS. Они проверяют жизненный цикл и очистку, но не заменяют проверку настоящих артефактов на устройстве. Реальный Android/Waydroid и полная установка в среде разработки не запускались.

## Реплеи: `replays/<seed>/<время>(N).md`

Реплей — Markdown-файл, кадр базы — в `replays/images/`. Числа читаются только из
fenced-блоков с известным info-string (`yaml`, `frames`, `state`); проза, ссылка
на картинку и чужие блоки игнорируются. Формат, правила разбора, сверка раскладки
и команды `replays`/`play` — в [REPLAY.md](REPLAY.md).

Нужна пересборка TAS (`cargo build --release` из корня): формат файла сменился,
старый `logs/replay.json` больше не читается — снимите запись заново. Команда
`clear` теперь чистит только консоль, файлы реплеев не удаляет.

## Карта памяти агентов

Рядом с `TAS/` и `stones/` должен сохраняться каталог `memory/` с `offsets.js`. Оба Frida-агента загружают из него адреса, сигнатуры и смещения. При первом обновлении до этой версии пересоберите приложение: `cargo build --release`. Дальнейшие изменения только карты требуют перезапуска/перезагрузки агента, но не пересборки. Подробности — в [MEMORY.md](MEMORY.md).
