# Установка и запуск через start/

В `start/` ровно два исполняемых файла:

- `install.sh` — зависимости, серверы и сборка TAS;
- `start.sh` — развёртывание серверов в Waydroid, проверки, запуск TAS и очистка.

## Требования

Linux x86_64 с CachyOS/Arch Linux или Ubuntu/Debian, графическая сессия с Konsole, `sudo`, уже установленный и инициализированный Waydroid с Android x86_64 и игрой. Установка самого Waydroid, Android-образа и APK зависит от дистрибутива и не выполняется этими скриптами.

Запускайте скрипты от обычного пользователя, **не через sudo**. Привилегии запрашиваются для отдельных операций. Для установки нужен интернет (pacman или APT, GitHub, Google Android SDK, Rust, crates.io и PyPI) и несколько гигабайт свободного места.

## Установка

Из корня проекта:

```bash
./start/install.sh
```

На CachyOS/Arch используется `pacman -S --needed --noconfirm`: только зависимости TAS, **без полного обновления системы и без синхронизации баз** (`-y`). Уже актуальные пакеты пропускаются; выбранные зависимости и необходимые им пакеты могут быть обновлены. Обновление ОС и обслуживание зеркал остаются под контролем пользователя. Если зеркало недоступно или сохранённая база ссылается на удалённые пакеты, установщик остановится с ошибкой — он не переключается на `-Syu` и не меняет зеркала автоматически. Закройте другие менеджеры пакетов перед установкой.

Команды `./start/install.sh` и `./start/start.sh` можно вызывать и из fish: скрипты запускаются своим Bash-интерпретатором. Если вы уже находитесь в каталоге `start/`, используйте `./install.sh` и `./start.sh` соответственно.

Установщик:

1. Автоматически выбирает `pacman` для CachyOS/Arch или `apt-get` для Ubuntu/Debian и устанавливает ADB, компиляторы, libclang, OpenSSL, JDK 17, Python/venv/PyYAML, Konsole и утилиты. В Arch `venv` входит в пакет `python`. Для SDK и сборки используется установленный JDK 17 без изменения системной Java по умолчанию.
2. При отсутствии Cargo устанавливает Rust stable через официальный rustup.
3. Устанавливает отдельный Android SDK в каталог данных TAS. Проверяет архив инструментов по контрольной сумме из HTTPS-манифеста Google. Лицензии Android предлагается прочитать и принять интерактивно.
4. Получает `NoortZee/phantom_keymaper` на закреплённом коммите `bc4f338488f03f229e9a9812e4b48baee56a45d8` и собирает **Android-компонент `phantom-server.jar`**, необходимый TAS. Десктопный mapper/GUI для работы TAS не нужен и не устанавливается.
5. Скачивает модифицированный сервер из релиза `x86` репозитория `NoortZee/phantom-frida`, проверяет закреплённый SHA-256 архива, выбирает ELF x86_64 и устанавливает его под именем `sysmon`. Обычный upstream frida-server вместо него не используется.
6. Создаёт отдельный Python venv с версией клиента Frida из `third_party/frida-rust/frida-sys/FRIDA_VERSION`.
7. Выполняет `cargo build --release`. Если `config.yaml` отсутствует, создаёт его с правами 600; существующий файл не перезаписывает.

Артефакты, SDK и исходники внешних проектов находятся в `${XDG_DATA_HOME:-$HOME/.local/share}/kot-tas`, а не в Git. Повторная установка не перезаписывает локальные изменения в клоне Phantom. Для обновления закреплённых версий нужно явно обновить коммит/URL/контрольную сумму установщика.

### Ошибка проверки Phantom origin

Установщик проверяет сохранённый в локальном клоне адрес `remote.origin.url`. HTTPS и SSH для `NoortZee/phantom_keymaper` равнозначны; пользовательские правила Git `insteadOf` сохраняются и не вызывают ложного отказа. Самостоятельно менять origin или удалять существующий клон скрипт не будет.

Если ошибка остаётся, проверьте локально:

```bash
git -C "${XDG_DATA_HOME:-$HOME/.local/share}/kot-tas/src/phantom_keymaper" config --local --get-all remote.origin.url
```

Ожидается один адрес репозитория `NoortZee/phantom_keymaper` на GitHub. Не публикуйте URL, если в нём есть токен или пароль. При другом origin сначала убедитесь, что это нужный клон, и исправьте адрес вручную; локальные изменения не удаляйте.

Предупреждение SDK Manager о переходе на Android CLI не является причиной ошибки origin: в данном сценарии установщик продолжает работу, если команды SDK завершились успешно.

Проверьте координаты и настройки Telegram в `config.yaml`: пример содержит фиктивный токен. Для отключения уведомлений установите `telegram.enabled: false`.

## Запуск

Запустите Waydroid и откройте King of Thieves, затем:

```bash
./start/start.sh
# Другой конфиг:
./start/start.sh /absolute/path/to/config.yaml
# Другой ADB-адрес:
TAS_ADB_DEVICE=192.168.240.113:5555 ./start/start.sh
```

При запуске используются **три консоли**:

1. Отдельное окно Konsole **TAS — Frida server** с foreground-сервером sysmon.
2. Отдельное окно Konsole **TAS — Phantom server** с foreground-сервером Phantom.
3. Исходный терминал, где после проверок готовности запускается интерактивный TAS.

В каждом новом окне может потребоваться пароль sudo: кеш sudo бывает привязан к терминалу. Введите его в обоих окнах. Серверные окна должны оставаться открытыми во время работы TAS. Вместо удалённых `nohup ... &` используются удерживаемые подключения `sudo waydroid shell` с `exec` сервера. Закрытие серверного окна останавливает всю TAS-сессию.

ADB-адрес по умолчанию: `192.168.240.112:5555`.

Лаунчер выполняет `adb kill-server`, `adb start-server`, подключается к указанному устройству и проверяет доступность root через `su`, ABI, запущенную игру и версию `sysmon`. Затем перезапускает старые sysmon/Phantom, копирует серверы в `/data/local/tmp`, запускает их в отдельных окнах Konsole и создаёт пробросы:

```text
tcp:41337 → localabstract:/data/local/tmp/sysmon.sock
tcp:27183 → tcp:27183
```

Локальные порты читаются из `frida.device` и `phantom.port` выбранного YAML; localhost обязателен. Внутренний Android-порт Phantom — 27183. Пробросы создаются с `--no-rebind`. Проверяется настоящий PING/PONG Phantom и перечисление процессов через Frida, а не только открытие TCP-сокета.

TAS запускается с переданным конфигом и рабочим каталогом проекта. Отдельный наблюдатель каждые несколько секунд проверяет Frida RPC, доступность игры, PID серверов и серверные окна, а также продлевает sudo-сессию исходного терминала. Phantom PING выполняется до старта TAS, но не во время игры: отключение дополнительного клиента Phantom вызывает `cancelAll` и может помешать вводу. Если проверка не проходит, работа завершается с очисткой.

## Завершение и ограничения

**Ctrl+C во время команды TAS** отменяет текущую запись, повтор или LIVE и возвращает главное меню. Серверные окна и ADB-пробросы при этом остаются запущенными. Лаунчер пересылает SIGINT в отдельную группу TAS и продолжает ждать завершения приложения; наблюдатель игнорирует терминальный SIGINT.

Для полного выхода используйте `exit` / `q` в меню. Ctrl+C в самом меню завершает TAS согласно его текущему обработчику. До запуска TAS Ctrl+C отменяет развёртывание с очисткой.

При полном выходе, ошибке TAS, ошибке развёртывания, SIGTERM или закрытии терминала (SIGHUP) обработчик завершения:

- останавливает TAS и наблюдатель;
- закрывает оба созданных окна Konsole и их группы процессов;
- останавливает Android-процессы по PID-файлам этой сессии с проверкой имени процесса;
- удаляет удалённый временный каталог и только созданные этой сессией пробросы;
- выключает ADB-сервер;
- сохраняет локальную диагностику в `${XDG_DATA_HOME:-$HOME/.local/share}/kot-tas/sessions/session.*` (путь печатается при запуске и выходе).

`health.log` и `watch.log` заранее открываются обычным пользователем, до привилегированных операций и старта TAS. Если открыть их нельзя, запуск прервётся до развёртывания серверов. Во время мониторинга используются уже открытые дескрипторы: изменение прав записи к пути не должно прерывать исправную сессию. Лаунчер не выполняет рекурсивный `chown` и не ослабляет права доступа. Причины сбоя sudo, Frida/игры и проверки Android PID выводятся раздельно.

В каталоге диагностики находятся `sysmon.log`, `phantom.log`, `health.log` и созданные для сессии скрипты. Даже если сервер сразу завершится, его вывод не теряется после очистки. Старые каталоги диагностики можно удалить вручную после разбора ошибки.

Код выхода TAS сохраняется. При невозможности очистить Android-процессы выводится предупреждение с путём каталога сессии. Для Android-очистки используется Waydroid, поэтому она возможна и при потере ADB. Установка и запуск сериализованы через `flock`.

**Важно:** перезапуск/выключение ADB влияет на другие ADB-сессии пользователя. Старые sysmon и Phantom в Waydroid принудительно останавливаются. Не запускайте параллельно независимую сессию, использующую эти же серверы. Phantom слушает `0.0.0.0` внутри Android, как в ручном сценарии; используйте доверенную сеть.

Обработчик не может выполниться после SIGKILL, отключения питания или аварии ОС. Если сам контейнер исчез, завершить процессы внутри него невозможно; для обычных ошибок, сигналов и выхода очистка выполняется автоматически.

## Проверки без Android

ShellCheck — необязательный инструмент разработки, он не устанавливается как зависимость TAS. Для выполнения соответствующей команды установите его отдельно.

```bash
bash -n start/install.sh start/start.sh
shellcheck start/install.sh start/start.sh
python3 -m unittest discover -s tests -v
```

Тесты используют имитации ADB, sudo, Waydroid, Frida и TAS. Они проверяют жизненный цикл и очистку, но не заменяют проверку настоящих артефактов на устройстве. Реальный Android/Waydroid и полная установка в среде разработки не запускались.

## Replay: текстовый сценарий и JSON

Список кадров между строками `"""` разбирается отдельно от JSON-тела. Числа из `timeline_ns`, RNG и физических кадров не являются прыжками; JSON-скобки не должны вызывать предупреждений о незакрытых циклах. Для старого сценария без разделителей разбор кадров останавливается перед JSON-объектом.

Если предыдущая версия показывала 257 прыжков вместо 13 и огромный таймаут, сначала обновите и **пересоберите** TAS (`cargo build --release` из корня). Загрузчик не перезаписывает replay при чтении, поэтому файл с корректным исходным JSON обычно не требует повторной записи. Повреждённые или вручную изменённые файлы нужно проверять отдельно. Команда `clear` удаляет replay — не используйте её для устранения этой ошибки без резервной копии.
