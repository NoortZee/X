# История изменений

История версий и пояснения к изменениям хранятся здесь, а не в заголовках исходников.
Версия Rust-приложения, версия JS-агента и версия игры — разные обозначения.
Исторические записи ниже перенесены из комментариев исходного кода; даты там не были указаны.

## Без выпуска — CachyOS / Arch Linux

- Установщик автоматически выбирает pacman или apt-get и использует соответствующие имена зависимостей.
- На CachyOS/Arch выполняется полное обновление `pacman -Syu --needed`, без частичного обновления.
- Для Android SDK явно выбирается установленный JDK 17, без изменения системной Java по умолчанию.
- Добавлены тесты выбора пакетного менеджера и обработки ошибок установки.

## Без выпуска — установка и запуск

- Добавлены `start/install.sh` и `start/start.sh` для Ubuntu/Debian и существующего Waydroid x86_64.
- Установка использует закреплённый модифицированный Phantom Android server и проверяемый по SHA-256 релиз phantom-frida, без подмены обычным frida-server.
- Добавлены проверки конфигурации, ABI, root, версии Frida, протоколов серверов и игры.
- Запуск управляет PID серверов, ADB-пробросами и очисткой после завершения TAS, ошибок и сигналов.
- Добавлены mock-тесты жизненного цикла; инструкция — в `docs/START.md`.

## Без выпуска — структура проекта

- Основное Rust-приложение и TAS-агент перенесены из `src/` и корня в `TAS/`.
- Rust-код сканера перенесён из `src/stones.rs` в `stones/mod.rs`.
- Настройки сканера и Telegram выделены в `stones/config.rs`.
- JS-хук сканера остаётся в `stones/rival_hook.js`.
- В `Cargo.toml` явно задана точка входа `TAS/main.rs`.
- Обновлены пути поиска TAS-агента; конфигурация и runtime-файлы остаются в корне проекта.
- Формат YAML, команды CLI и алгоритмы записи, повтора и перебора не менялись.

## Rust-приложение — 0.2.0

Текущая версия в `Cargo.toml`. Отдельная история этого выпуска в исходном репозитории не описана.

## TAS-агент — v5.7

- Наблюдение за игрой и монитор вызовов JUMP; основной сценарий повтора отправляет ввод через Phantom.
- SMART-резолвер FRAME_FUNC принимает единственное совпадение AOB даже при сдвиге функции.
- При отсутствии совпадений используется резервное смещение с диагностикой; при нескольких выбирается ближайшее к ожидаемому.
- Уточнённая сигнатура FRAME_FUNC содержит хвост `41 89 F4 48 89 FB 8B 87 B0 00 00 00`.
  Чтение `+0xB0` отличает HeroBody от FrogBody/BoilerBody, которые совпадали со старой сигнатурой.
- Ленивое подключение покадрового обработчика для записи и повтора.
  Старый комментарий упоминал `main.py`; текущий управляющий код — `TAS/main.rs`.
- Оптимизация горячего пути чтения физического состояния: один `try/catch`, без `findRangeByAddress`.
- `detectFrameAtStart` используется для расчёта среднего FPS за время записи.

## Stones-хук — v6

- Смещения RivalDungeon/Item собраны в `RIVAL_FIELDS` / `ITEM_FIELDS` для обновления при изменении игры.
- Проверяются первые пять событий `rival_update`: диапазоны gold, player_level и корректность n_items.
- При подозрительных данных отправляется `rival_data_suspect`.
- Если все пять снимков подозрительны, отправляется `rival_data_invalid` с подсказкой проверить offsets/AOB.

## Stones-хук — v5

- Добавлен AOB-поиск парсера по 36-байтовому префиксу с резервным смещением.

## Stones-хук — v4

- Снимок соперника выполняется в `onLeave`.
- Добавлен журнал последних 50 соперников.

## Совместимость

Сигнатуры и резервные смещения в исходных комментариях относились к King of Thieves **2.84.1, x86_64**, библиотеке `libthieves.so`.
Это не гарантия совместимости с другими сборками.
Для HeroBody указан FRAME_FUNC `0x1612A20`; старая сигнатура также находила другое тело по `0x161B7C0`.
При обновлении игры необходимо перепроверять сигнатуры функций и смещения полей в обоих JS-агентах.
