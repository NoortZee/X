# История изменений

История версий и пояснения к изменениям хранятся здесь, а не в заголовках исходников.
Версия Rust-приложения, версия JS-агента и версия игры — разные обозначения.
Исторические записи ниже перенесены из комментариев исходного кода; даты там не были указаны.

## Без выпуска — стеки и значения в диагностике Catacombs

- В hero_control добавлены ограниченные по частоте стеки ACCURATE/FUZZY с библиотекой/RVA и caller; отдельная bounded-таблица сохраняет уникальные стеки независимо от кольцевого лога.
- Снимки героя включают текущие физические поля TAS и контакты; ошибки чтения полей изолированы от наблюдения вызовов. Смещения направления/контактов и лимиты стеков хранятся в memory/offsets.js.
- Исправлено чтение имени RTTI: до NUL, с жёстким ограничением длины, без захвата соседних строк.
- В отчёт добавлены метаданные процесса/библиотеки с явным отличием версии профиля от версии игры. Новые конструкторные хуки по непроверенным RVA не добавлялись.
- Добавлены тесты NUL/границы имени, дедупликации/лимитов/частоты стеков, RVA и FUZZY fallback. README не изменён.

## Без выпуска — контрольные хуки Catacombs

- Добавлен read-only hero_control по общей уникальной сигнатуре FRAME_FUNC, без RVA fallback.
- Явные счётчики входа всех шести хуков увеличиваются до чтения полей; старые frames/requests сохранены.
- Добавлены ограниченные по частоте снимки объекта/vptr/RTTI и last_hero, RTTI-смещения вынесены в общий профиль. Ошибка RTTI не отключает контроль.
- Добавлены тесты счётчика до ошибки, частоты снимков, успешного и ошибочного RTTI, игнорирования вызовов после stop. Инструкция описывает сравнение обычного уровня и события.

## Без выпуска — уточнение сигнатуры CollectSkulls

- Общий 44-байтный пролог collect_request заменён 117-байтной сигнатурой до `45 89 7C 24 18` включительно из предоставленного дампа по RVA `0xE4E650`. По проверке пользователя новая сигнатура уникальна; рантайм продолжает независимо требовать ровно одно совпадение.
- rel32 трёх прямых вызовов остаются wildcard. Добавлен тест совпадения с дампом, изменения rel32 и отклонения другого окончания при прежнем общем прологе.
- Ранее исправленный replay_update (`48 8B BB`) сохранён. Rust-код и README не изменены, пересборка для этой правки карты не требуется.

## Без выпуска — исправление сигнатуры ReplayState update

- В `memory/offsets.js` исправлен ModR/M байт сигнатуры replay_update: `48 8B 83` → `48 8B BB`, согласно предоставленному пользователем дампу файла и работающей игры по RVA `0x13EF310`. Это `mov rdi, [rbx+0x160]`, не `mov rax, [rbx+0x160]`.
- Добавлена регрессия по присланным байтам: сигнатура совпадает, допускает изменение rel32 вызова, отвергает прежний неверный байт. Уникальность во всём модуле по фрагменту не подтверждается — её по-прежнему проверяет рантайм.
- Уточнение Itanium ABI: `0x20090F8` из отчёта — начало `_ZTV11ReplayState` с заголовком, address point находится по `+0x10`, слот 22 по `0x20091B8`. В текущем диагностическом модуле vtable не используется для установки хуков.

## Без выпуска — исправление зависания Catacombs start

- Подключён ScriptHandler перед load/install: в используемой Frida-привязке он необходим также для доставки RPC-ответов. Без него start мог бесконечно ждать ответ.
- Добавлен call_cancellable: ожидание ответа проверяет отмену каждые 50 мс, имеет тайм-аут и отбрасывает запоздалые ответы других RPC по ID. Обычный call теперь также ограничен 30 секундами.
- Catacombs передаёт существующий флаг Ctrl+C: install ждёт до 30 секунд, status/dump до 5 секунд. При ошибке первой установки скрипт выгружается. Удалено лишнее ожидание stop RPC при очистке.
- JS-ошибки Catacombs выводятся в терминал; добавлены source-level регрессии Rust-интеграции. Они не заменяют сборку и тест на устройстве.

## Без выпуска — диагностика Catacombs

- Добавлен отдельный opt-in модуль `catacombs/`: команды start/status/dump/stop в меню TAS, выгрузка перед detach.
- Read-only хуки ReplayState update/spawn, DeathSkull update, addSkulls и билдера CollectSkulls; ограниченные буферы и JSON-отчёт в logs.
- Профиль-кандидат из предоставленного статического анализа хранится в общей карте памяти; уникальность всех сигнатур проверяется до установки хуков, без RVA fallback. Ошибка чтения/валидации снимает хуки.
- Автосбор, телепорт, noclip и изменение наград не реализованы: недостающие проверки и порядок эксперимента описаны в `docs/CATACOMBS.md`.
- Добавлены mock-тесты opt-in, неоднозначных сигнатур, rollback установки, runtime-валидации и отсутствия операций записи.

## Без выпуска — общая карта памяти

- Сигнатуры функций, резервные RVA, смещения полей, размеры/шаги структур и платформенная раскладка времени вынесены в `memory/offsets.js`.
- TAS и stones загружают карту с диска через общий `TAS/memory.rs` и обращаются к разделам `MEMORY_LAYOUT`, без локальных копий адресов.
- Добавлены проверка архитектуры перед запуском агента и ошибка при отсутствии/пустом файле карты, без fallback на встроенные значения.
- Добавлены Node-тесты загрузки обоих агентов и чтения изменённых значений из карты, Rust-тесты загрузчика и инструкция `docs/MEMORY.md`.

## Без выпуска — серверы без дополнительных окон

- Frida/sysmon и Phantom работают через фоновые локальные подключения Waydroid, удерживающие foreground-серверы внутри Android.
- Konsole и tee больше не требуются и не устанавливаются; весь вывод серверов направлен в сохранённые логи.
- Пароль sudo запрашивается в исходном терминале, фоновые подключения используют `sudo -n` и не читают ввод TAS.
- Сохранены отдельные группы процессов, контроль готовности/завершения, отмена команды TAS по Ctrl+C и очистка ресурсов при полном выходе.
- Mock-тесты проверяют отсутствие окон, ранний/поздний отказ фонового подключения, логи и жизненный цикл.

## Без выпуска — Ctrl+C и границы replay

- Лаунчер пересылает Ctrl+C в отдельную группу TAS и продолжает ожидание, позволяя отменить команду и вернуться в меню без остановки серверов.
- Наблюдатель не завершается от терминального SIGINT; полный выход и другие сигналы сохраняют очистку ресурсов.
- Парсер списка кадров и метаданных ограничен текстовым блоком replay, а не всем файлом: JSON-числа больше не добавляются как прыжки, JSON-скобки не считаются концами циклов.
- Для старых сценариев без разделителей разбор останавливается на начале JSON-тела; исправлено небезопасное байтовое усечение Unicode при поиске JSON.
- Добавлены тест SIGINT группе терминала и четыре Rust-регрессии для replay, включая roundtrip 13 прыжков с timeline/body_frames.

## Без выпуска — стабильная диагностика монитора

- `health.log` и `watch.log` открываются от обычного пользователя до запуска привилегированных команд и TAS; монитор переиспользует файловые дескрипторы вместо повторного открытия путей.
- Проверки sudo, Frida/игры и Android PID выдают отдельные причины остановки вместо общего сообщения о потере серверов.
- Добавлен регрессионный тест с потерей прав записи к каталогу и логам после старта TAS: исправная сессия продолжает работу и запись диагностики.

## Без выпуска — отдельные серверные консоли

- Frida/sysmon и Phantom запускаются в двух отдельных окнах Konsole через foreground Waydroid-сессии, без удалённого `nohup ... &`.
- TAS остаётся в исходном терминале и запускается только после протокольной проверки готовности.
- Добавлен контроль закрытия окон/завершения серверных команд и очистка созданных групп процессов.
- Вывод серверов и диагностика сохраняются в каталоге данных TAS после завершения.
- Убраны сообщения об отсутствующем `/proc/PID/cmdline` при очистке уже завершившихся серверов.
- Konsole добавлен в зависимости; жизненный цикл отдельных консолей проверяется mock-тестами.

## Без выпуска — проверка origin Phantom

- Проверяется локальный `remote.origin.url`, а не адрес транспорта после преобразования Git `insteadOf`.
- Разрешены эквивалентные HTTPS/SSH-адреса `NoortZee/phantom_keymaper` с `.git` или без него.
- Чужие репозитории, подменные хосты и неоднозначные множественные URL отклоняются; адреса с возможными секретами не выводятся.
- Добавлены тесты на настоящих локальных Git-репозиториях, включая воспроизведение `insteadOf`.

## Без выпуска — без обновления системы

- Установщик CachyOS/Arch использует `pacman -S --needed` без `-y` и `-u`: больше не запускает обновление всей ОС.
- ShellCheck исключён из обязательных зависимостей: это инструмент разработки, не требование TAS.
- Регрессионные тесты проверяют отсутствие синхронизации баз и полного обновления.

## Без выпуска — CachyOS / Arch Linux

- Установщик автоматически выбирает pacman или apt-get и использует соответствующие имена зависимостей.
- Первоначально использовался `pacman -Syu --needed`; это поведение отменено изменением выше.
- Для Android SDK явно выбирается установленный JDK 17, без изменения системной Java по умолчанию.
- Добавлены тесты выбора пакетного менеджера и обработки ошибок установки.

## Без выпуска — установка и запуск

- Добавлены `start/install.sh` и `start/start.sh` для Ubuntu/Debian и существующего Waydroid x86_64.
- Установка использует закреплённый модифицированный Phantom Android server и проверяемый по SHA-256 релиз phantom-frida, без подмены обычным frida-server.
- Добавлены проверки конфигурации, ABI, root, версии Frida, протоколов серверов и игры.
- Запуск управляет PID серверов, ADB-пробросами и очисткой после завершения TAS, ошибок и сигналов.
- Добавлены mock-тесты жизненного цикла; инструкция — в `docs/START.md`.

## Rust-приложение — 0.2.0

Текущая версия в `Cargo.toml`. Отдельная история этого выпуска в исходном репозитории не описана.

## TAS-агент — v5.7

- Наблюдение за игрой и монитор вызовов JUMP; основной сценарий повтора отправляет ввод через Phantom.
- SMART-резолвер FRAME_FUNC принимает единственное совпадение AOB даже при сдвиге функции.
- При отсутствии совпадений используется резервное смещение с диагностикой; при нескольких выбирается ближайшее к ожидаемому.
- Уточнённая сигнатура FRAME_FUNC содержит хвост `41 89 F4 48 89 FB 8B 87 B0 00 00 00`.
  Чтение `+0xB0` отличает HeroBody от FrogBody/BoilerBody, которые совпадали со старой сигнатурой.
- Ленивое подключение покадрового обработчика для записи и повтора.
  Старый комментарий упоминал `main.py`; текущий управляющий код — `TAS/main.rs`.
- Оптимизация горячего пути чтения физического состояния: один `try/catch`, без `findRangeByAddress`.
- `detectFrameAtStart` используется для расчёта среднего FPS за время записи.

## Совместимость

Сигнатуры и резервные смещения в исходных комментариях относились к King of Thieves **2.84.1, x86_64**, библиотеке `libthieves.so`.
Это не гарантия совместимости с другими сборками.
Для HeroBody указан FRAME_FUNC `0x1612A20`; старая сигнатура также находила другое тело по `0x161B7C0`.
При обновлении игры необходимо перепроверять сигнатуры функций и смещения полей в обоих JS-агентах.
